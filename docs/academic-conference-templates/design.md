# 学术会议报告模板设计（AI/ML 顶会）

> 适用范围：NeurIPS / ICML / ICLR / CVPR / ACL 等 AI/ML 类顶会。
> 用途：参会团队写给**领导团队汇报**的参会报告（与现有 GTC 日报同一定位）。
> 交付物：本说明文档 + 两个 HTML 样例（`daily-report-sample.html`、`summary-report-sample.html`）。

---

## 一、背景与设计原则

现有项目里的日报 / 总结报告模板面向 **industry 会议（如 GTC）**，调性是"参会收集竞争 / 市场情报"。本设计提供**学术会议版本**，核心是把同一套"参会报告给领导看"的骨架，从行业语境迁移到学术（AI/ML 顶会）语境。

**四条设计原则：**

1. **沿用 GTC 日报的"领导汇报"DNA + session 导入模型** —— 日报仍按 session 组织、支持从会议 session 数据库直接导入、自动初始化模块、字段可增删。
2. **内容单位从"行业 session"改为"学术 paper / talk"** —— 字段换成学术维度（方法 / 贡献 / 结果 / 资源链接 / 论文类型）。
3. **现场情报类版块大幅缩减** —— 学术会议的现场/竞争情报重要性远低于行业展会，把 GTC 的三个情报版块（现场情报 / 圈内声音 / 深度研判）瘦身。
4. **保留并强化"趋势研判 / 对我们的启示"** —— 这是领导最关心、最先翻的地方。

## 二、核心词汇对照（industry → 学术）

| 现有 GTC（industry） | 学术版 | 说明 |
|---|---|---|
| 日报 / DAILY BRIEFING | **参会日报 / 每日简报** | 头部 eyebrow 保留 |
| 核心要点 | **今日要点** | 每日 TL;DR |
| 相关议题（session 分组） | **论文与议程**（按研究主题分轨） | 内容单位 = 论文 / talk |
| session：关键收获 + 启示 | **研究方法与核心贡献 + 实验结果 + 局限与对我们的启示** | 论文三件套 |
| speakers（姓名 / 职务 / 公司） | **作者与机构** + 论文类型 + 资源链接 | 学术看机构与可复现性 |
| 现场情报（竞争情报） | ~~删除~~ | 学术现场情报价值低 |
| 圈内声音（行业声音） | ~~删除~~（精华并入"现场速记"） | 同上 |
| 深度研判（市场研判） | **趋势研判**（保留、改名） | 领导核心版块 |
| 现场记录 / 展会近距离 | **现场速记**（轻量） | 海报区 / 会场照片 + 软信息 |
| —（新增） | **待跟进**（可选） | 给领导的 action list |

## 三、日报模板

### 3.1 骨架对比

| 版块 | GTC（industry） | 学术版 | 取舍 |
|---|---|---|---|
| 头部 | 标题 + 核心要点 | 标题 + **今日要点** | 保留 |
| 主体 | 相关议题（session 分组） | **论文与议程**（session 分组） | 保留，字段换学术 |
| 情报① | 现场情报 | — | 砍 |
| 情报② | 圈内声音 | — | 砍 |
| 情报③ | 深度研判 | **趋势研判** | 保留、改名 |
| 现场 | 现场记录 / 展会照片 | **现场速记**（轻量） | 大幅缩减 |
| 新增 | — | **待跟进**（可选） | action list |

### 3.2 主体：论文与议程（按 session 导入）

每个从数据库导入的 session = 一个可折叠模块。**默认字段**（全部支持增删）：

| 字段 | 类型 | 说明 |
|---|---|---|
| 作者与机构 | 结构化（姓名 / 机构，可多个） | 取代 GTC speakers；学术看机构 |
| **类型** | 标签选择 | Oral / Spotlight / Poster / Workshop / Tutorial / Keynote / Award |
| 研究方法与核心贡献 | 富文本 | 论文做什么、怎么做、新在哪（对应 GTC「关键收获」） |
| 实验结果 / 基准 | 富文本 | 数据、SOTA 对比、benchmark（学术特有） |
| 局限与对我们的启示 | 富文本 | 论文短板 + 对我们团队的意义（对应 GTC「启示」，领导最关心） |
| 资源链接 | 链接列表 | arXiv / 代码 / 数据集 / 项目页（学术特有，支撑复现） |
| 插图 | 图片 | 论文图表、现场拍的 slide |
| 贡献人 | 成员标签 | 同 GTC，记录谁覆盖了这篇 |

**分组方式**：沿用 GTC 的"按研究主题（topic）聚合 + 可拖拽排序"，主题由 session 的 `mainTopic` 或研究方向映射。

### 3.3 趋势研判（领导核心版块）

单一大块富文本（沿用 GTC 深度研判形态），提示写：**今天最值得关注的 1–2 个方向性信号 / 方法论 shift / 对我们的机会或威胁**。这是领导翻日报时最先看的地方。

### 3.4 现场速记（轻量，可选）

把原"现场情报 + 圈内声音"压缩成一个轻量块，可选地记：走廊交流（hallway track）、招聘 / 人才动向、评审或复现性争议等"软信息"。可留空。海报区 / 会场照片也放这里，不再单列大版块。

### 3.5 待跟进（可选）

action list：精读哪些论文、复现哪些代码、联系哪些人 / 实验室、跑哪些内部实验 + 负责人。

### 3.6 继承自 GTC 的功能（不动）

- 从会议 session 集合导入 + 按 date 过滤 + 自动初始化模块
- 多人协作、贡献人标签、在线 presence
- 版本快照 / 历史回滚
- 导出 Markdown、分享链接、邮件简报
- TOC 目录、折叠 / 展开

### 3.7 功能需求（供后续实现）

1. 日报基于「会议 session 集合」导入模型，按日期过滤、自动建模块（同 GTC `DailyReport.jsx` 的 auto-init 逻辑）。
2. 每个 session 模块的字段可**增删**（"加载模块、添加字段"）。
3. 「类型」字段为预设标签下拉（Oral / Spotlight / Poster / Workshop / Tutorial / Keynote / Award）。
4. 「资源链接」支持 arXiv / GitHub / 数据集 / 项目页 等结构化链接。

## 四、总结报告模板

### 4.1 定位

整场会议的**战略性综述**。日报是"按天按 session 捕获"，总结报告是"跨整天提炼给领导"。是给**不会读日报的领导**看的唯一一份大报告。

建议主体走**结构化模板**（与日报一致、可填可协作）；若暂时沿用 HTML 上传，本设计也可直接作为 HTML 模板的内容大纲。

### 4.2 版块设计

| # | 版块 | 必要性 | 内容 | 说明 |
|---|---|---|---|---|
| 1 | **会议概览** | 必要 | 会议名称 / 届次、时间地点、规模（投稿 / 录用 / 接收率）、分轨（Main / Workshop / Tutorial / D&B）、我方参会人与覆盖分工 | 给领导 30 秒背景 |
| 2 | **执行摘要 / 核心结论** | 必要 | 3–5 条 TL;DR：本届 headline 信息、最大变化、对我们的 top 机会 / 威胁 | **领导最先看、可能只看这块** |
| 3 | **研究主题全景** | 必要 | 整场会议的主题地图：热点主题（如 scaling / RLHF / diffusion / MoE / agents）、在涨 / 在退、方法论 shift；每主题一行 + 代表论文 | 大盘视角 |
| 4 | **重点论文精选** | 必要 | 5–10 篇必读（含 best paper / award）：每篇一张紧凑卡片——问题 / 方法 / 结果 / 为什么重要 | 日报的精炼短名单 |
| 5 | **关键趋势与信号** | 推荐 | 横切分析：benchmark 格局、SOTA 谁推到哪、数据集 / 资源趋势、冒头子方向 | 比主题全景更深一档 |
| 6 | **对我们的启示与建议** | 必要 | 要投的方向、可内部落地的方法、能力差距、风险、招聘 / 合作信号（关注哪些人 / 实验室） | **领导要 action 的地方** |
| 7 | **待跟进事项** | 推荐 | action list：精读哪些论文、复现哪些代码、联系哪些人、跑哪些内部实验 + 负责人 / 时间 | 闭环 |
| 8 | **附录** | 可选 | 完整覆盖清单（谁覆盖了哪些 session）、资源链接、参考文献 | 存档 |

> 第 3 与第 5 都涉及"趋势"，分工：第 3 是**主题地图（what）**——哪些主题在涨；第 5 是**横切信号（so what / deeper）**——benchmark 格局、SOTA 推进、资源趋势。若内容不多可合并为一节。

### 4.3 与日报的衔接

- 第 4「重点论文精选」= 从所有日报 session 里**人工精选**，每篇可一键引用日报已有字段（方法 / 结果 / 启示），避免重写。
- 第 3「研究主题全景」+ 第 5「关键趋势与信号」= 把每天日报的「趋势研判」**跨天汇总升华**。
- 第 2「执行摘要」= 全篇浓缩，**最后写**。

### 4.4 形态说明

当前 GTC 总结报告（`ConferenceReport.jsx`）只是 HTML 上传容器。学术版建议做成**结构化模板**（和日报同款可协作编辑器），8 个版块即 8 个可填模块；过渡期也可先把本设计当 HTML 大纲套用。

## 六、后续实现建议（不在本次范围）

本次只产出设计稿与样例。若后续要落地到 app，建议的工作拆分：

1. **i18n 词条**：在 `src/i18n/zh-CN.json` / `en-US.json` 新增学术版 report 键（或用 namespace 区分 industry / academic）。
2. **会议类型字段**：在 conference 文档加 `type: 'industry' | 'academic'`，日报 / 总结报告按类型切换版块与字段集。
3. **日报组件**：复用 `DailyReport.jsx`，把硬编码的 GTC 版块抽成可配置；新增学术字段（类型标签、资源链接、实验结果）。
4. **总结报告组件**：把 `ConferenceReport.jsx`（现为 HTML 上传容器）升级为可选的结构化编辑器，复用日报的编辑 / 协作 / 导出能力。
5. **硬编码清理**：`reportUtils.js` 的 `generateSummaryId`、导出文件名 `GTC2026_*` 等需按会议类型参数化。
